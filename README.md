# Real-Time E-Commerce Clickstream & Analytics Data Engineering Platform

> A real-time data engineering platform that simulates e-commerce customer activity, streams events through Apache Kafka, processes them with Apache Spark Structured Streaming, and transforms them through a Bronze → Silver → Gold architecture for business analytics.

---

## 📌 Project Overview

This project demonstrates an end-to-end **real-time data engineering pipeline** for an e-commerce environment.

The system simulates customer activity such as:

* Product page views
* Adding products to cart
* Checkout attempts
* Successful payments
* Failed payments

These events are continuously generated by a Python-based event generator and published to **Confluent Cloud Kafka**.

**Apache Spark Structured Streaming** consumes the Kafka events and processes them through multiple data layers:

```text
Python Event Generator
        │
        ▼
Confluent Cloud Kafka
        │
        │  ecommerce_events
        ▼
Spark Structured Streaming
        │
        ▼
┌─────────────────────────┐
│      Bronze Layer       │
│ Raw streaming events    │
│ Stored as Parquet       │
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│       Silver Layer      │
│ Cleaning & Validation   │
│ Structured event data   │
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│        Gold Layer       │
│ Business Analytics      │
└────────────┬────────────┘
             │
      ┌──────┴──────────────────────────┐
      ▼                                 ▼
Revenue Analytics              Customer Behaviour
      │                                 │
      ├── Product Revenue              ├── Funnel Analysis
      ├── Category Revenue              ├── Session Analysis
      ├── Total Revenue                ├── Payment Analysis
      └── Payment Summary              └── Cart Abandonment
```

The project focuses on the practical implementation of a streaming data pipeline rather than only performing analysis on a static dataset.

---

# 🎯 Project Objectives

The main objectives of the project are to demonstrate how a modern data engineering pipeline can:

1. Generate realistic e-commerce events.
2. Stream events through Apache Kafka.
3. Consume streaming data using Spark Structured Streaming.
4. Parse and structure incoming JSON events.
5. Store processed streaming data in a Bronze layer.
6. Clean and validate data in a Silver layer.
7. Build business-oriented analytics in a Gold layer.
8. Analyze customer sessions and purchasing behaviour.
9. Detect potential cart abandonment.
10. Maintain a secure and reproducible project structure.

# 📦 Event Model

The Python event generator produces e-commerce events representing different stages of a customer's journey.

## Event Types

### `page_view`

Represents a customer viewing a product.

Example conceptual flow:

```text
User → Product Page
```

### `add_to_cart`

Represents the customer adding a product to their shopping cart.

```text
User → Product → Cart
```

### `checkout_attempt`

Represents the customer beginning the checkout process.

```text
Cart → Checkout
```

### `payment_success`

Represents a successful payment.

```text
Checkout → Successful Payment
```

### `payment_failed`

Represents an unsuccessful payment attempt.

```text
Checkout → Failed Payment
```

# 📡 Kafka Streaming Layer

The project uses **Confluent Cloud Kafka** as the streaming platform.

Kafka provides the event transport layer between the Python event generator and Spark Structured Streaming.

## Kafka Topic

```text

```

The Python producer publishes JSON events to this topic.

Spark then subscribes to the topic and continuously consumes the events.

```text

   │ JSON event

   │
```

# 🥉 Bronze Layer

The Bronze layer is the first storage layer of the data pipeline.

## Purpose

The main purpose of Bronze is to capture incoming streaming data in a persistent format that can be processed by downstream layers.

The Spark Bronze job:

1. Connects to Kafka.
2. Reads Kafka messages as a streaming DataFrame.
3. Extracts the Kafka message value.
4. Parses the JSON event.
5. Structures the event data.
6. Writes the resulting data as Parquet.

## Storage

```text
data/
└── bronze/
```

The Bronze layer is stored using **Apache Parquet**.

Parquet provides a columnar storage format suitable for analytical processing.

---

# 🥈 Silver Layer

The Silver layer transforms Bronze data into cleaner and more reliable structured data.

## Silver Processing

The pipeline performs validation and transformation operations such as:

### JSON parsing

Raw event information is converted into structured Spark columns.

### Event validation

Expected event types are checked:

```text
page_view
add_to_cart
checkout_attempt
payment_success
payment_failed
```

### Price validation

The pipeline validates price-related values.

### Quantity validation

The pipeline validates quantity-related values.

### Data quality checks

The Silver layer checks whether the transformed data meets the expected structure and business rules.

## Storage

```text
data/
└── silver/
```

The Silver layer is also stored as Parquet.

# 🛒 8. Cart Abandonment Detection

One of the main business analytics features of the project is cart abandonment detection.

The implemented business rule is:

```text
IF
checkout_attempt_count > 0
AND
payment_success_count = 0

THEN

cart_abandonment = "yes"
```

Otherwise:

```text
cart_abandonment = "no"
```

Conceptually:

```text
                Checkout?
                   │
             ┌─────┴─────┐
             │           │
            No          Yes
             │           │
         Not enough      ▼
          evidence    Payment?
                         │
                   ┌─────┴─────┐
                   │           │
                  Yes          No
                   │           │
                Completed    Abandoned
```

Output:

```text
data/gold/cart_abandonment/
```

A summary is also generated:

```text
data/gold/abandonment_summary/
```

# ▶️ Running the Pipeline

## Step 1 — Start the event generator

From the project root:

```powershell
python Producer\event_generator.py
```

The generator continuously produces e-commerce events.

---

## Step 2 — Run Bronze Processing

Run the Spark Bronze job:

```powershell
spark-submit --packages org.apache.spark:spark-sql-kafka-0-10_2.12:3.5.9 src\spark_bronze.py
```

The job consumes Kafka events and writes them to:

```text
data/bronze/
```

---

## Step 3 — Run Silver Processing

Run:

```powershell
spark-submit src\spark_silver.py
```

The Silver job reads Bronze data, performs validation/transformation, and writes:

```text
data/silver/
```

---

## Step 4 — Run Gold Processing

Run:

```powershell
spark-submit src\spark_gold.py
```

The Gold job generates:

```text
data/gold/
```

including revenue, payment, funnel, session, and cart-abandonment analytics.
